# Compare Two SDS Archives

`compare_mseed_outputs.py` compares any two MiniSEED/SDS trees. The first tree is
called `--reference` and the second tree is called `--candidate`, but those names
do not imply any specific converter.

Typical use cases:

- Compare an SDS archive generated by `yfile2miniseed` with an existing SDS
  archive.
- Compare a raw converted SDS tree with an ObsPy-cleaned SDS tree.
- Compare two versions of the same archive after a conversion or cleanup change.

Use MiniSEED 2 for workflows that rely on ObsPy. The normal ObsPy MiniSEED path
in this project setup does not assume MiniSEED 3 support.

## Quick Example

```bat
python tools\compare_mseed_outputs.py ^
  --reference D:\ExistingSDS ^
  --candidate D:\OurSDS ^
  --report D:\SDS_compare_report ^
  --level medium ^
  --id-mode strict
```

Report files:

```text
comparison_summary.csv
comparison_summary.json
mismatches.txt
```

## Levels

`simple` is the fastest level. It reads headers and compares IDs, time span,
sample rates, sample counts, and file counts.

```bat
python tools\compare_mseed_outputs.py ^
  --reference D:\ExistingSDS ^
  --candidate D:\OurSDS ^
  --report D:\SDS_compare_simple ^
  --level simple ^
  --id-mode strict
```

`medium` is still header-based, but also compares coverage, gap counts, and
overlap counts.

```bat
python tools\compare_mseed_outputs.py ^
  --reference D:\ExistingSDS ^
  --candidate D:\OurSDS ^
  --report D:\SDS_compare_medium ^
  --level medium ^
  --id-mode strict
```

`deep` reads sample data and compares ObsPy-cleaned streams. The deep path uses:

```python
Stream.merge(method=-1)
```

This is conservative cleanup. Compatible duplicates and safe overlaps may be
merged; conflicting overlap sample values are not silently forced into one
trace.

Use `deep` on smaller subsets first:

```bat
python tools\compare_mseed_outputs.py ^
  --reference D:\ExistingSDS ^
  --candidate D:\OurSDS ^
  --report D:\SDS_compare_deep_TST ^
  --level deep ^
  --station TST ^
  --max-deep-samples 2000000
```

## Important Options

```text
--reference          First SDS tree.
--candidate          Second SDS tree.
--report             Output report folder.
--level              simple, medium, or deep.
--id-mode strict     Compare full NET.STA.LOC.CHA.
--id-mode component  Compare NET.STA.LOC plus the last channel letter.
--default-network    Network code to use when a trace has an empty network.
--station            Optional station filter. Repeatable.
--channel            Optional channel filter. Repeatable.
--date-from          Include traces ending at/after this UTC time.
--date-to            Include traces starting at/before this UTC time.
--max-deep-samples   Safety limit for deep sample comparison.
--fail-on-difference Return exit code 1 when differences are found.
```

Use `--id-mode strict` for normal archive validation. Use `--id-mode component`
only when you intentionally want to ignore band-code differences and compare by
the final component letter.

## Result Status Values

```text
OK               No difference at the selected level.
DIFF             Both trees have the key, but at least one check differs.
ONLY_REFERENCE   The key exists only in the reference tree.
ONLY_CANDIDATE   The key exists only in the candidate tree.
SKIPPED_TOO_LARGE
                 Deep comparison skipped this key because it exceeded
                 --max-deep-samples.
```

## Suggested Workflow

1. Run `simple` on the full SDS archive.
2. If that is clean, run `medium` on the full SDS archive.
3. Run `deep` on selected stations, dates, or channels.
4. Inspect `mismatches.txt` first, then open `comparison_summary.csv` for detail.
